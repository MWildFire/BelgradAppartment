# RentBelgrad — План для Claude Code

> Сборка продакшн-сайта, который **транслирует объявления из Telegram-канала [@RentBelgrad](https://t.me/RentBelgrad)** в каталог недвижимости, на дизайн-системе **«Belgrade Editorial»**.
>
> Этот файл — единственный источник правды для агента Claude Code. Читать сверху вниз, выполнять по фазам. Дизайн-токены — в `assets/tokens.css`. Визуальный эталон — `index.html` (главная) и `RentBelgrad Design System.html` (вайрфреймы всех экранов).

---

## 0. Принципы (анти-AI-slop)

Эти правила приоритетнее любого дефолта генератора компонентов.

- **Никаких** фиолетовых градиентов, glassmorphism-везде, Inter/Roboto по умолчанию, карточек со скруглением 16px и цветной полоской слева, эмодзи в UI, «AI-стоковых» иллюстраций.
- Типографика: **Unbounded** (дисплей) + **Golos Text** (текст) + **JetBrains Mono** (данные/цены/метки). Все три — с настоящей кириллицей.
- Палитра — приглушённый сербский флаг: оксблад `#A8362A`, навигатор `#15324C`, тёплая бумага `#F4EFE6`, охра `#D89A4E`. Фон **никогда** не чисто-белый.
- Геометрия резкая: радиусы 3–6px максимум, тени плоские/почти без размытия, тонкие hairline-линии `#D8CDBA`.
- Сетка редакционная и асимметричная, крупный типографический ритм, много воздуха. Цена и метраж — всегда моноширинным.
- Микрокопирайт — «свой человек», не корпоратив. Сербские топонимы кириллицей (Врачар, Дорћол). Цены в €, площадь как `48 m²`, комнаты как `1+1`.

## 1. Стек

| Слой | Выбор | Почему |
|---|---|---|
| Фреймворк | **Astro 4** (islands) + **React** для интерактивных кусков | контент-сайт, статика + ISR, минимум JS на клиенте |

| Хостинг | **Vercel**, ISR `revalidate: 600` | дешёвый автодеплой |
| Тесты | **Playwright** (e2e + визуальные снапшоты) | |

## 3. Ингест из Telegram → данные (ядро проекта)

Канал публичный, поэтому два надёжных пути. **Реализовать A, B держать как фолбэк.**

### Путь A — Bot API (предпочтительно, если есть доступ к каналу)
1. Создать бота через @BotFather, **добавить администратором** в @RentBelgrad.
2. Воркер слушает `channel_post` (webhook или long-poll). Каждый новый пост → в очередь парсинга.
3. Историю (старые посты) добрать один раз через путь B.

### Путь B — публичный веб-превью + Playwright (фолбэк / бэкофилл)
1. Канал доступен как `https://t.me/s/RentBelgrad` — статическая HTML-лента.
2. **`playwright-cli`** открывает страницу, скроллит вверх по `data-post`, собирает: текст, `<img>`-превью, ссылки на фото, дату, id поста.
3. Пагинация — через параметр `?before=<id>` до конца истории.

### Парсинг поста → структура
Посты идут по шаблону из дизайн-системы. Парсер вытаскивает поля регуляркой, **LLM-экстракция как фолбэк** для нестандартных постов.

```ts
type Listing = {
  id: string;            // tg msg id
  source: "telegram";
  postedAt: string;      // ISO
  price: number;         // EUR/мес
  currency: "EUR";
  area: number;          // m²
  rooms: string;         // "1+1"
  floor?: string;        // "3/5"
  district: string;      // "Врачар"
  address?: string;
  forVNJ: boolean;       // "✓ для ВНЖ"
  forWhiteCard: boolean; // белый картон
  amenities: string[];   // ["балкон","лифт","кондиционер"]
  status: "active" | "rented";  // "СНЯТО" → rented
  photos: string[];      // наши URL после перезаливки в Blob
  rawText: string;       // оригинал поста (фолбэк-отображение)
  tgLink: string;        // https://t.me/RentBelgrad/<id>
};
```

Правила нормализации:
- `€650 / месяц` → `price:650`. `48m²`/`48 м²` → `area:48`. `1+1` как есть.
- Бейдж `СНЯТО`/`сдано` → `status:"rented"` (показываем приглушённо, не удаляем — это соц.доказательство).
- Теги `для ВНЖ` / `белый картон` → булевы флаги (главные фильтры).
- Фото: скачать, перезалить в Blob, прогнать через `astro:assets` (webp, размеры).
- Дедуп по `id`; правки поста в ТГ → upsert.

## 4. Фазы сборки

### Фаза 0 — Каркас
- `npm create astro@latest`, Tailwind, React-интеграция.
- Перенести `assets/tokens.css` → `tailwind.config` (цвета, шрифты, spacing, радиусы 1-в-1).
- Self-host шрифты (`@fontsource-variable/unbounded`, `@fontsource/golos-text`, `@fontsource/jetbrains-mono`).
- Скопировать глобальные стили из `index.html`.

### Фаза 1 — UX-карта (`ui-ux-pro-max-skill` + `stitch`)
Экраны и состояния (эталоны — вайрфреймы + `index.html`):
- Главная (готова визуально в `index.html`).
- Каталог `/catalog` — фильтры (ВНЖ, картон, район, цена, комнаты), сортировка, пустое состояние, скелетоны.
- Карточка `/apt/[slug]` — галерея, параметры, блок «важно для релокантов», CTA, ссылка на исходный пост в ТГ.
- Калькулятор аренды (режие/инфостан/депозит).
- Форма заявки на персональный поиск.
- Профиль + избранное (черновик через `stitch`).
- Карта объектов (Leaflet + кластеры).

### Фаза 2 — Дизайн-проверка (`taste-skill` + `awesome-design-md`)
Каждый собранный экран → ревью: типографический ритм, контраст, сетка, не-slop. Фиксить до зелёного.

### Фаза 3 — Ингест-пайплайн
Реализовать раздел 3 (путь A + бэкофилл B). Выход: `content/listings/*.json` или таблица SQLite. Cron на Vercel (`/api/sync`, каждые 10 мин) + ручной `npm run sync`.

### Фаза 4 — Каталог и компоненты (`npxskillui` + `21st.dev`)
- `<ListingCard>` (макет уже в `index.html` — переиспользовать 1-в-1).
- `<FilterRail>`, `<RangeSlider>`, `<SearchCombobox>` — донор 21st.dev, перекрасить в токены.
- Каталог рендерит из данных, фильтры — клиентский island.

### Фаза 5 — Доп. экраны (+ опц. `webgpu-claude-skill`)
Карта, калькулятор, заявка, профиль. WebGPU-hero — только за флагом, по умолчанию выкл.

### Фаза 6 — Полировка и тесты (`impeccable` + `playwright-cli`)
- `impeccable`: оптические отступы, hover/focus/active, состояния загрузки/ошибки/пусто, prefers-reduced-motion, тёмная тема (опц.), a11y (контраст AA, фокус-кольца, alt).
- Playwright: e2e (поиск → каталог → карточка → CTA) + визуальные снапшоты ключевых страниц + проверка, что новый пост в ТГ доезжает до сайта.
- Lighthouse ≥ 95 perf/a11y/SEO. OpenGraph на карточках (цена+район+фото).
