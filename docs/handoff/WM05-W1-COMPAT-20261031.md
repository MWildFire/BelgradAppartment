### C1.1 Настройки вне `src/config.py`
`src/watermark/settings.py`: `WatermarkSettings(BaseSettings)` — все 9 полей `watermark_*` с теми же
именами env и умолчаниями, тот же `.env` (`PROJECT_ROOT/.env`), `extra="ignore"`,
`get_watermark_settings()` с `lru_cache`. Все обращения в `src/` переведены (и форма
`getattr(settings, "watermark_…", default)` в `lama.py` — из-за неё `get_lama_inpainter()` после выноса
полей стал бы молча `None`). Тесты (`tests/watermark/test_settings.py`): каждое имя из блока
Watermark `.env.example` читается и каждое поле описано; в `Settings` нет `watermark_*`;
`get_lama_inpainter()` не `None` при указанной модели (фейковый файл + подмена `torch.jit.load`).
Кеш настроек тесты не сбрасывают — они меняют поля у синглтона через `monkeypatch.setattr`;
16 файлов тестов переведены на `get_watermark_settings()` (механически + вручную особые случаи).

`SUBSCRIPTION_BOT_ENABLED=1` — один `Bot`, один `start_polling`, токен нужен; дерево роутеров следует
флагам. `deploy/otz-bot.service` и `tests/test_bot_unit.py` удалены.

### C1.3 Контракт kept
`MarkResult.kept_reason: str | None = None` (последнее поле, в `to_dict()`/`.wm.json`; старый sidecar
читается как `None`). Значения W1: `corner_mode` (угол Halo в режиме `skip`) и `lama_unavailable`
(нужна LaMa, её нет: центр Halo, угол в режиме `lama`). `get_inpainter("lama")` теперь возвращает
`None` вместо Telea; `plan_removal(tpl) → Removal(method, inpainter, kept_reason)`, `removal_for` — тонкая
обёртка прежней формы. Повтор после появления модели: `store._retry_available_lama` пересчитывает знаки с
`kept_reason == "lama_unavailable"` (и угол в режиме `lama` у sidecar R04), а `corner_mode`, `disabled`,
`self_check` — нет (тесты в `test_kept_reason.py`).

### C1.4 Без OpenCV — таблица замен

| Вызов OpenCV (где был) | Замена в `src/watermark/imgops.py` | Проверка против OpenCV |
|---|---|---|
| `cvtColor RGB2GRAY` (`detect.to_gray`) | `rgb_to_gray`: целочисленная BT.601, 15-бит (как в этой сборке cv2) | идентично побитно |
| `GaussianBlur(σ=1,3,4)` (`detect`, `remove`) | `gaussian_blur`: `gaussian_filter(mode="mirror")`, радиус `round(8σ+1)\|1` как у cv2 | ≤ 1e-3 float |
| `Sobel(ksize=3)` + `merge` | `sobel3` (`correlate1d`, зеркальная граница) + `gradient_field` (стек gx, gy) | ≤ 1e-3 |
| `resize` AREA / LINEAR (`detect`) | `resize(..., "area"/"linear")` — свои ядра cv2: площадь с дробными весами, полупиксельные центры | ≤ 1e-3 float |
| `resize` AREA / NEAREST / CUBIC (`lama`) | `resize(..., "area"/"nearest"/"cubic")`, cubic a=−0.75 | nearest — точно; uint8 ≤ 1 уровень |
| `matchTemplate(CCORR_NORMED)` по 2-канальному полю + `minMaxLoc` | `match_template_ccorr_normed`: float64 FFT, сумма по каналам, знаменатель из интегрального образа; `argmax` | \|Δ\| ≤ 1e-4 |
| `warpAffine` (сдвиг, bilinear, граница 0) | `translate_bilinear` со смещением, округлённым до 1/32 px, как фиксированная точка cv2 | ≤ 1e-4 |
| `dilate` (прямоугольник) | `dilate_square` (`maximum_filter`, граница не добавляет) | точно |
| `morphologyEx(GRADIENT)` | `morph_gradient` = dilate − erode, граница эрозии «+∞» как у cv2 | точно, включая край |
| `connectedComponentsWithStats(8)` | `connected_components_stats` (`ndimage.label` 3×3 + bbox/площадь) | то же разбиение и статистика; нумерация меткой может отличаться — алгоритм от неё не зависит |
| `distanceTransform(L2, PRECISE)` (`lama_corner`) | `distance_transform_l2` (`distance_transform_edt`) | ≤ 1e-4 |
| `inpaint(TELEA)` (`TeleaInpainter`: режим углов `telea` **и** краевая полоса CityExpert) | `classic_inpaint`: уравнение Лапласа на `scipy.sparse` (`splu`), 3 канала одной факторизацией | сравнение на фото ниже |

Примечание: `TeleaInpainter` в R04 — не только режим углов `telea`: им же заливается узкая полоса
по контуру результата reverse-blend (CityExpert), поэтому классическое заполнение живёт в конвейере
и вне режима `telea`. Имя класса и значение метода `inpaint:telea` сохранены ради совместимости sidecar
и отчётов; докстринг объясняет. `torch` в `imgops` не импортируется.

`tests/watermark/test_no_cv2.py`: (а) AST-скан `src/` и `scripts/` — нет импортов `cv2`;
`pyproject.toml`/`uv.lock` не содержат `opencv`; (б) подпроцесс с `sys.modules["cv2"] = None`
импортирует все модули `src.watermark`, `bot_daemon`, `wm_bot`, `site.photos`, `site.og_image` и
гоняет `clean_file` на синтетике каждого шаблона (LaMa — фейк), для режимов углов `skip` и `telea`,
и убеждается, что `torch` не загрузился. Синтетика `tests/watermark/synth.py` тоже переведена на
`imgops`.

## Решения и замечания для O / W2 / W3 / M

1. **`zida_logo` без LaMa.** Шаблон сам объявляет `lama_fallback: reverse_blend`; я сохранил этот
   детерминированный путь (метод `reverse_blend` виден в отчёте, это не Telea). Если W2 решит, что
   reverse-blend для 4zida без LaMa недопустим по качеству, достаточно убрать `lama_fallback` из
   `assets/zida_logo.json` или поставить `"telea"` — знак тогда будет **оставлен** с
   `lama_unavailable` (код менять не нужно). Качество этого пути без LaMa не мерил (его нет в
   поставляемой конфигурации с моделью).
2. **`halo_center` без LaMa** теперь оставляется (раньше шёл в Telea) — по решению 5 PLAN.
3. **Область влияния на W2/W3 при слиянии.** `pipeline.py` (`plan_removal`, `Removal`), `inpaint.py`
   (`get_inpainter` → `Inpainter | None`), `store.py` (`_retry_available_lama`), тесты
   настроек. `removal_for` сохраняет прежнюю форму `(method, inpainter)`. W2 добавляет значения
   `disabled`/`self_check` в `plan_removal`/самопроверку; `_kept_for_missing_lama` ничего другого
   повторно не пересчитывает.
4. **scipy на проде — транзитивная зависимость** (`imagehash`), а не прямая: `uv export --frozen --no-dev
   --extra clip` даёт scipy 1.17.1, numpy 2.4.6, Pillow 12.2.0, torch 2.12.0. Менять
   `pyproject.toml` нельзя (решение 1), поэтому `imgops` полагается на то, что `imagehash` останется
   в основных зависимостях. P проверяет `python -c "import scipy"` в `/opt/otz/.venv`.
5. **Скорость на CityExpert** ×1.8–1.9 из-за гауссовых фильтров в подборе k (scipy вместо SIMD cv2);
   абсолютно 0.9 с на фото; если W3-замер на Linux покажет проблему — ускорение возможно уменьшением
   сетки k, но это меняет результаты.
6. Нумерация компонент связности у `ndimage.label` не совпадает с OpenCV; алгоритм `opacity_map` от неё не
   зависит (проверено сверкой пикселей).
7. `rm -rf` в `$WM/tmp/wm05/w1` у меня запрещён — остатки прерванного запуска эталона перезаписаны
   следующим прогоном, лишних файлов нет.
