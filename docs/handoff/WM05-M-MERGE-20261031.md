## 2. Слияние: конфликты и решения

Конфликтов W1+W2 нет. W3 конфликтовал в трёх файлах:

- `src/watermark/lama.py` — версия W3 целиком (у W2 был только патч бюджета кропа и старое `DEFAULT_MAX_PIXELS = 105_000`).
  После слияния `DEFAULT_MAX_PIXELS == 75_000`, `watermark_lama_max_pixels == 75000`.
- `src/watermark/pipeline.py` — структура `_remove_mark` W2 (самопроверка, выключатель, рост маски), вызов `remove_inpaint`
  обёрнут обработкой `LamaError` W3: сбой воркера → знак оставлен (`skip`, `kept_reason="lama_unavailable"`), пиксели не тронуты.
  Ранний `return` не даёт самопроверке W2 перетереть эту причину.
- `.env.example` — оба блока (`WATERMARK_DISABLED_KINDS` и лимиты LaMa). `settings.py` слился сам; есть и
  `watermark_disabled_kinds`/`disabled_kinds()`, и `watermark_lama_*`, `watermark_torch_threads`.

Две правки тестов после слияния (в коммите `3e01298`), продуктовый код не менялся:

1. Синтетическое фото Halo 1000×750 (4:3) имеет маску LaMa 7 % кадра, а у W2 потолок 5,5 %: такая метка теперь
   оставляется как `self_check` **до** обращения к воркеру. Тесты W3, которые хотели дойти до воркера
   (`test_lama_isolation.py`, `test_wm_bot_daemon_scenarios.py`), переведены на портретный кадр 800×1000
   (маска 4,1 %). Добавлены два теста: сбой воркера на `halo_center` с маской < 5,5 % → `skip` + `lama_unavailable`,
   пиксели не изменились (замечание I2 R-W3), и ландшафтный кадр → `self_check`, воркер не запускался.
2. `test_clean_on_but_nobody_allowed_and_no_subscriptions_means_nothing_to_serve` зависел от порядка запуска:
   миграционные тесты Alembic отключают существующие логгеры (`fileConfig`), поэтому `caplog` был пуст; логгер
   демона включается явно (как в `test_r03_engine_tails.py`).

## 5. Инцидент в ходе прогона (устранён, на выпуск не влияет)

В скрипте сравнения «не сломать» я задал `GIT_DIR=<repo>/.git` на весь прогон pytest. Фикстуры `tests/test_release.py` делают
`git init/add/commit` во временном каталоге, и из-за `GIT_DIR` один такой коммит (`fixture`) попал в настоящий репозиторий
поверх `3e01298`. Рабочие файлы и остальные ветки не пострадали; ветка возвращена на `3e01298` через `git update-ref` с проверкой
старого значения, индекс — через `git read-tree HEAD` (без `reset --hard`), `git status` и `git diff HEAD` пусты. Недействительный прогон
удалён, «не сломать» повторено без глобального `GIT_DIR` (он остался только для одного файла с `git cat-file`, чтение).
