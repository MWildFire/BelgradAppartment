### Реалии-vs-план дельты (зафиксировано при ревью Wave 0)

- **Опечатки «Воџовац» НЕТ.** `data/districts.yaml:36` уже содержит корректное `"Вождовац": Vozdovac` (+ `"Voždovac": Vozdovac`). Grep по dze-варианту `Воџовац` (U+045F) — 0 совпадений. → Задача **S1-3** сводится к добиванию **незамапленных латинских районов** + логированию, без правки опечатки.
- **CSS — один файл `site.css`.** Плановая ownership-таблица предполагала раздельные CSS для каталога (Wave 1) и apt (Wave 2). Чтобы параллельные frontend-агенты не конфликтовали: **Wave 1 владеет `static/css/site.css`** (грид/карточка/CTA), **Wave 2 заводит новый `static/css/apt.css`** (секция карты на `/apt/{id}`), подключаемый через `{% block head %}` в `apt.html`. `base.html` в Wave 1–2 не трогаем.
- **Координаты уже проброшены.** `SiteListingView.lat/lon` уже заполняются (`readmodel.py:103-104`). Wave 2 backend добавляет `coords`/`maps` в контекст `/apt/{id}`, не меняя схему.
- **Yandex-builder уже есть** (`src/post/location.py:12` `yandex_maps_url`), но он строит **точный пин** (`pt=`) для ТГ-постов Дарьи. Для фуззи публичного сайта пин не нужен → builder **расширяется** параметром `precise: bool = True` (дефолт сохраняет старое поведение ТГ-постов precise), а `maps_links` зовёт его с `precise=False`. Дублирования нет.

## S0-2 — Диагностика реальной недоступности (де-риск Wave 3)

> Прогон с dev-машины `2026-06-24T00:01Z`. Цель — зафиксировать ИСХОДНОЕ состояние до CF, обосновать фикс.

### Что измерено
```
dig rentbelgrad.com A         → 90.156.254.159           (RU-origin, прямой A-record, без CF)
dig admin.rentbelgrad.com A   → 90.156.254.159           (admin тоже светит origin-IP — обоснование D4)
dig rentbelgrad.com NS        → launch1.spaceship.net, launch2.spaceship.net   (регистратор Spaceship — цель смены NS)
curl -I https://rentbelgrad.com → HTTP/2 405, allow: GET  (405 = HEAD не разрешён; GET=200. Caddy, HSTS, CSP, alt-svc h3)
прямой заход на 90.156.254.159:443 (--resolve) → HTTP/2 405 — ORIGIN СЕЙЧАС ОТКРЫТ НАРУЖУ (нет IP-lock)
```

### Выводы
1. **Origin-IP полностью открыт** на 80/443 для прямого захода — Wave 3 origin-lock (`scripts/cf_ufw_allowlist.sh`, S3-2) это закроет.
2. **И `rentbelgrad.com`, и `admin.rentbelgrad.com` резолвятся в один RU-IP** — admin-сабдомен светит origin → подтверждает дефолт **D4** (admin тоже за CF).
3. **TLS/HTTP работают** (HTTP/2+HTTP/3, HSTS, CSP с `cdn.jsdelivr.net`) — Caddy/Let's Encrypt здоров. Под CF переходим на **Origin CA cert + Full(Strict)** (S3-1), т.к. ACME HTTP-01 ломается под прокси.
4. **С dev-сети сайт доступен** (200 на GET) — переменная недоступность «с мобильных/из других стран» НЕ воспроизведена с этой точки. Это ожидаемо: проблема — вариативность RU-origin маршрутизации из части мобильных AS/стран, которую CF-anycast закрывает архитектурно.
